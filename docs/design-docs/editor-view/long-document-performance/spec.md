# Feature: 回复交互与长文档性能优化

**作者**: Codex  
**日期**: 2026-08-12  
**状态**: Quick Draft（用户已确认问题 1、3 进入修改，评论图片不在本期）

---

## 1. 背景 (Background)

### 1.1 问题描述

- 评论卡片中的“回复...”入口首次点击会先选中并定位评论，第二次点击才打开输入框。
- Obsidian 文档达到约 2 万字后，启用插件会出现明显卡顿；停用插件后立即恢复。

### 1.2 现状分析

- 回复入口默认使用 `opacity: 0` 和 `pointer-events: none`，仅在卡片 `:hover` 后可命中；首次点击可能穿透到卡片定位事件。
- 编辑器每次文档变化都会把 CodeMirror 文档完整转换为字符串，并为全部标注更新锚点。
- 锚点位置通过从文首扫描到 offset 计算行列，成本随文档长度和标注数共同增长。
- 表格标注渲染器在没有表格 Widget 时仍可能创建全文字符串和行索引。
- Decoration 在几乎所有 transaction 上全量重建，包括光标与选区变化。

### 1.3 主要使用场景

- 用户点击评论卡片底部“回复...”并一次进入输入状态。
- 用户在包含评论或高亮的长 Markdown 文档中连续输入、移动光标、滚动和撤销。
- 用户编辑包含或不包含 Markdown 表格的长文档。

## 2. 目标 (Goals)

- 回复入口首次点击直接打开输入框，不触发卡片定位。
- 降低长文档普通编辑路径中的全文复制、全文扫描和无关 Decoration 重建。
- 保持锚点移动、失效、恢复、表格标注和外部标注刷新行为兼容。
- 创建约 2 万字 Markdown 样本文档，并以自动化测试和性能基准验证改动。

### 2.1 非目标 (Non-Goals)

- 不支持评论图片或正文图片评论。
- 本期不重写阅读模式渲染算法；仅在性能数据证明它仍是瓶颈时另行处理。
- 不修改 sidecar schema、评论数据模型或飞书同步协议。

## 3. 需求细化 (Requirements)

### 3.1 功能性需求

- “回复...”入口保持原有位置、颜色和 hover 时显示的视觉逻辑；点击其所在整行一次显示并聚焦 textarea。
- 普通文档编辑不得无条件调用全文 `toString()`。
- 活跃锚点文本仍匹配时，使用 CodeMirror `Text` 的局部读取和行信息更新锚点。
- 锚点失效或恢复需要全文搜索时，最多按一次编辑事务延迟创建一次全文字符串。
- 没有表格 Widget 时，表格渲染器不得创建全文字符串或全文行索引。
- 光标或选区变化不得触发普通标注 Decoration 全量重建；显式标注变化仍能刷新。
- 重新加载文档时，原位置文本仍匹配的有效锚点直接复用。

### 3.2 非功能性需求

- 不引入新的持久化格式和升级步骤。
- 2 万字、多个标注的连续输入基准应较修改前显著降低耗时，且普通活跃锚点路径不发生全文物化。
- 所有既有测试、TypeScript 构建、格式检查通过。
- 新增测试覆盖正常路径、边界条件和失效/恢复等异常路径。

## 4. 设计方案 (Design)

### 4.1 方案概览

- 回复交互保留原有 hover 视觉样式；由 composer 整行接收首次点击，按钮显示后继续阻止冒泡。
- 编辑锚点更新接口接收 CodeMirror `Text`，普通路径通过 `sliceString`、`lineAt` 和局部上下文构造锚点。
- 全文字符串采用事务内惰性缓存，仅供锚点重新定位的慢路径使用。
- 引入专用 Decoration 刷新 effect，替代“任意 transaction 都刷新”的条件。
- 表格渲染先检查 Widget，再决定是否建立源码快照。

### 4.2 兼容性约束

- 已解决标注不参与实时锚点更新。
- 活跃标注被编辑破坏后仍变为 orphaned；内容恢复后仍可重新激活。
- 新增、删除、改色、创建评论待选区等显式状态变化仍刷新编辑和表格标注。

## 5. 备选方案 (Alternatives Considered)

- 仅延长保存 debounce：无法减少发生在 debounce 前的同步全文开销，因此不采用。
- 长文档直接关闭标注：会损失核心功能，因此不采用。
- 只拦截评论卡片事件：可能导致首次点击既不定位也不打开回复框，因此不采用。

## 7. 测试计划 (Test Plan)

### 7.1 单元测试

- 活跃锚点在文首插入、文末追加、标注内部修改、恢复文本时的状态和位置。
- 惰性全文物化只在重新定位慢路径发生。
- 无表格 Widget 时不刷新全文源码快照。
- 专用 effect 能刷新标注，普通 selection transaction 不触发重建。

### 7.2 集成测试

- 回复入口首次点击显示并聚焦输入框，且不调用卡片定位。
- 全量现有测试与构建通过。

### 7.3 性能测试

- 创建约 2 万中文字 Markdown 样本。
- 使用 0、20、100 个标注测量文首和文末连续编辑。
- 比较优化前后锚点更新耗时与全文物化次数。
